Endpoints

MethodPathDescription
GET /health Health check. Returns {"status":"healthy"}.
GET /api/v1/users List demo shop profiles.
GET /api/v1/users/{user_id} Get a single shop profile.
POST /api/v1/voice/parse-text Parse a typed Roman-Urdu transaction string into ledger entries.
POST /api/v1/voice/transcribe Upload an audio file for Whisper transcription + parsing.
GET /api/v1/ledger List ledger entries for a user.
POST /api/v1/ledger/batch-confirm Create and confirm multiple ledger entries at once.
GET /api/v1/dashboard/{user_id} Get the shopkeeper dashboard (profit, trends, insight).
GET /api/v1/evidence-profile/{user_id} Consent-gated evidence summary for lenders or partners.
PATCH /api/v1/evidence-profile/{user_id}/consent Grant or revoke sharing consent.

Demo shop IDs

shop_001 shop_002 shop_003

Consent gate example

The evidence endpoint never returns data unless both the user has granted consent in the app and the caller sends the X-User-Consent: true header.

Request

curl -H "X-User-Consent: true" \
  https://karobar-saathi.onrender.com/api/v1/evidence-profile/shop_001

Revoke consent

curl -X PATCH \
  -H "Content-Type: application/json" \
  -d '{"has_user_consented_to_share":false}' \
  https://karobar-saathi.onrender.com/api/v1/evidence-profile/shop_001/consent

Limitations

  • Demo data only — every Render restart resets the three seeded shops.
  • No authentication; the demo app is hard-wired to shared demo accounts.
  • "Financial readiness" is a rule-based heuristic, not a trained credit model.
  • Voice transcription relies on free-tier Groq Whisper, which has rate limits.
  • This is a proof of concept, not a production lending or accounting service.
